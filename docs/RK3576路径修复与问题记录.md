## 1. 用户报的现象

```
Tronlong@RK3576-Tronlong:/rm_inventor_fly/tools$ bash run_rk3576.sh
Cannot open camera config: /home/Tronlong/apps/rm_inventor_fly-89fe1cf-20261111/Camera/camera_config.yaml
```

项目从 `/home/Tronlong/apps/rm_inventor_fly-89fe1cf-20261111` 挪到了 `/rm_inventor_fly`，旧目录已不存在。

---

## 2. 根因：不是脚本写死了路径

`tools/run_rk3576.sh` 本身用 `HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"` 相对定位，**没有写死绝对路径**。真正的旧路径来自编译产物：

| 位置 | 内容 |
|---|---|
| `build/CMakeCache.txt` | `CMAKE_HOME_DIRECTORY=/home/Tronlong/apps/rm_inventor_fly-89fe1cf-20261111`<br>`MVS_ROOT=/home/Tronlong/apps/.../sdk/MVS` |
| 二进制 `build/Camera/show` | 编译期宏 `DEFAULT_CAMERA_CONFIG_PATH="<旧目录>/Camera/camera_config.yaml"`<br>`DEFAULT_RECORDING_DIR="<旧目录>/Camera/../recordings"`（CMake `target_compile_definitions` 用 `${CMAKE_CURRENT_SOURCE_DIR}` 生成） |

脚本只在「二进制不存在」或显式 `--rebuild` 时才重新构建，所以旧二进制被一直沿用 → 启动时去读不存在的旧配置。

## 3. 发现的问题清单（按排查顺序）

| # | 问题 | 现象 | 根因 | 处置 |
|---|---|---|---|---|
| 1 | **编译期路径失效（主诉）** | `Cannot open camera config: /home/Tronlong/apps/...` | CMake 缓存与二进制宏仍指向旧目录；脚本不触发重建 | 脚本加「缓存源码路径陈旧检测 → 自动重建」＋运行时显式 `--config` |
| 2 | **build 目录删不掉** | `rm: cannot remove '/rm_inventor_fly/build': Permission denied` | 项目根 `/rm_inventor_fly` 是 `root:root 755`，Tronlong 无权删除父目录下的目录项（虽然 build 目录自身属 Tronlong） | 改为 `find build -mindepth 1 -maxdepth 1 -exec rm -rf` **只清空内容、保留目录** |
| 3 | **录像目录建不了** | 重建后 `mkdir: cannot create directory '/rm_inventor_fly/recordings': Permission denied`，脚本 `set -e` 中止 | 同上，根目录 root 所有 | `sudo mkdir` + `chown Tronlong`；脚本里的 `mkdir` 改为**非致命**（失败只告警，默认无 `--recording` 启动不需要该目录） |
| 4 | **相机枚举失败** | `No Hikrobot camera found.`（但 `lsusb` 能看到 `2bdf:0001 MV-CS016-10UC`） | USB 节点 `/dev/bus/usb/002/005` 是 `crw-rw-r-- root root`，普通用户只读；项目自带的 `99-hikrobot.rules` **没随部署包传上板** | 上传规则文件并 `sudo cp` 到 `/etc/udev/rules.d/`，`udevadm control --reload-rules` + `udevadm trigger --subsystem-match=usb`；节点变为 `crw-rw-rw- root plugdev` |
| 5 | **`--recording` 到点不退出** | 录完 3 秒不结束，`timeout` 退出码 124；日志无 `[RECORDING] Saved`、无 `Captured ...` | **源码 bug**：`OutputWorker::stop()` 只置 `stopping_`，但 `visionLoop()` 循环条件是 `while (!stopRequested_)`，而 `stopRequested_` 只在录像失败/按 q 时才置位 → `worker_.join()` 永久阻塞 | `stop()` 开头补一行 `stopRequested_.store(true, std::memory_order_relaxed);`，板端 + 本地源码各修一处 |
| 6 | **空/损坏配置会 abort**（顺带发现，未修） | 一次测试命令引号被 Windows 解析吃掉，生成了空配置，程序抛未捕获 `cv::Exception` → `Aborted (134)` | `cv::FileStorage` 读空文件抛异常，`main` 未捕获 | **仅记录，未修改**（不属于本次路径修复范围） |

补充：`XOpenDisplay Fail` 是 headless（无 DISPLAY）下 MVS SDK 的无害警告，不影响取流。

### 4.1 `tools/run_rk3576.sh`（本地 + 板端同步）

原 882 B → 现 3356 B，md5 `5f2ec8cceb3b453c1bbafda081a37aaf`（两端一致）。

| 改动 | 说明 |
|---|---|
| 新增 `BUILD` / `CONFIG` 变量 | 全部相对 `HERE` 推导，不写死路径 |
| 新增 `CONFIG` 存在性检查 | 配置缺失时明确报错 |

| `mkdir -p recordings` 改为非致命 | 失败只告警，不中止启动 |
| **运行时显式 `--config "$CONFIG"`** | 双保险：即使二进制仍是旧宏也能启动；且 `calibration.file: "../camera_intrinsics.yaml"` 会由程序相对**配置文件所在目录**解析（不是 cwd）。用户自带 `--config`/位置参数时不追加，保持自定义优先 |
| 保留 `--rebuild` | 手动强制重编入口 |

### 4.2 `Camera/CameraSetting.cpp`（板端 + 本地各一处，同一行）

```cpp
void stop() {
    // visionLoop() 的循环条件是 !stopRequested_；只置 stopping_ 会让它
    // 永远不退出，join() 挂死（--recording 到点后进程无法结束）。
    stopRequested_.store(true, std::memory_order_relaxed);   // ← 新增
    {
        std::lock_guard<std::mutex> lock(mutex_);
        stopping_ = true;
    }
    condition_.notify_one();
    if (worker_.joinable()) worker_.join();
}
```

- 板端：打了补丁并 `--rebuild` 重新编译（备份 `Camera/CameraSetting.cpp.bak`，30333 B）。
- 本地：`git diff` 为 `Camera/CameraSetting.cpp | 3 +++`（注释 2 行 + 代码 1 行），**未提交**。

> 这个 bug 在两个版本里都存在，属于源码基线问题，不是板端特有。

## 7. 回退方式

```bash
# 脚本回到原版
cp /rm_inventor_fly/tools/run_rk3576.sh.bak /rm_inventor_fly/tools/run_rk3576.sh

# 源码回到修复前（随后必须重编，否则二进制仍是补丁版）
cp /rm_inventor_fly/Camera/CameraSetting.cpp.bak /rm_inventor_fly/Camera/CameraSetting.cpp
cd /rm_inventor_fly && bash tools/run_rk3576.sh --rebuild

# 撤销 udev 规则（撤销后普通用户又枚举不到相机）
sudo rm /etc/udev/rules.d/99-hikrobot.rules
sudo udevadm control --reload-rules

# 本地工作区
git checkout -- Camera/CameraSetting.cpp
```

## 8. 现在怎么启动

```bash
cd /rm_inventor_fly
bash tools/run_rk3576.sh                 # 无窗口取流 + 检测（默认，无限循环，Ctrl+C / timeout 结束）
bash tools/run_rk3576.sh --window        # 板子桌面终端：显示叠框窗口
bash tools/run_rk3576.sh --recording     # 按 camera_config.yaml 的 record_seconds(60) 录像后自动退出
bash tools/run_rk3576.sh --rebuild       # 强制重新配置 + 编译
bash tools/run_rk3576.sh --config /path/to/other.yaml   # 自定义配置
```

脚本会自动处理：MVS SDK 库路径（`LD_LIBRARY_PATH`、`MVCAM_COMMON_RUNENV`）、源码目录迁移后的重建、配置路径、录像目录。
**注意别用根目录的 `run.sh`** —— 那是 WSL 版（依赖 usbipd / `/opt/MVS`），板端不适用。
