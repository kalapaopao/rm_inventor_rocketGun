# 标定与绿色圆灯精调

运行仍使用 `./run.sh --window --config Camera/camera_config.yaml`；
将配置中的 `vision.enabled` 改为 1 后才启用视觉，默认纯取流行为不变。
`vision.calibration.file` 相对于配置文件所在目录解析。
启用视觉及标定后启动日志应出现 `[Calibration] loaded ... size=[1440 x 1080]`。
标定文件缺失/矩阵无效时拒绝启动；帧尺寸不一致时发布无效结果。

处理顺序：原图模型检测 → 模型 ROI 内 HSV 绿色分割 → 轮廓面积/圆度/椭圆轴比筛选
→ 椭圆拟合中心（绿色圆灯灯心）→ 像素卡尔曼跟踪 → 当前/未来灯心去畸变 → 光轴视线角。
白色高亮不再单独作为通过依据。多个合格圆灯目前选择 ROI 内面积最大的一个；
阈值是可调初值，需用真实靶灯、过曝和杂光视频验证，不能视为比赛验收结果。

不对整帧执行去畸变，避免额外全图处理与模型输入分布变化；
显示/检测/预测/现有串口始终使用原图像素坐标。
`VisionResult.currentYaw/currentPitch` 与 `futureYaw/futurePitch` 单位为弧度，
右/下为正，分别以 `currentAnglesValid/futureAnglesValid` 判断有效性。
它们是相机光轴视线角，不是镖架控制角、距离或三维坐标。
8/10 秒预测仍是图像匀速外推，不代表物理落点预测。
串口随后改为水平像素偏差8字节帧，不发送角度字段；以 [SerialYawProtocol.md](SerialYawProtocol.md) 为准。

验证：`cmake --build build -j2`，然后
`./build/Vision/vision_geometry_test ./camera_intrinsics.yaml`。
合成测试覆盖标定读取、主光轴角、尺寸/越界保护、圆灯灯心、白光/绿色灯条排除。
实际灯心在叠框图中为黄十字和绿圆；真实相机精度仍须现场验证。

## 准心与 yaw 调试显示

图像几何中心增加长十字准心（1080 高原图约 120 像素跨度），不是标定主点。
左上角 `yaw_offset_px` 为当前滤波灯心到瞄准线的水平像素偏差；
另外显示串口状态、最近成功写出的偏差和发送/错误计数，不再显示角度作为待发参数。
无有效结果显示 `N/A`，不以0冒充检测成功。默认瞄准线是图像整数中心，
所以灯心在准心上时像素偏差为0。内参计算的光轴角保留在结果结构中，不作为串口输出。
串口仍默认关闭，下位机超时保护及物理电控联调完成后才能启用。

协议参考（2026-11-10 查阅，非本机已联调协议）：
- [Misaka21/dart 串口实现](https://github.com/Misaka21/dart/blob/main/hardware/serial/serial_thread.cpp)：
  视觉发送 int16 水平像素偏差，固定8字节包；不是绝对 yaw 角。
- [HERO 镖体视觉串口实现](https://github.com/Ruakker/dart_vision_26/blob/dart_body/src/uart.c)：
  发送检测标志、yaw/pitch、角速度和距离，不能把镖体协议原样当镖架协议。
本次选择参考的8字节兼容帧，没有有效标志、序号和CRC，这是保留风险；
失效时停止发送，下位机必须独立判断超时。后续若增强协议需双方同步升级。
