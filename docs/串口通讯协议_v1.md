## 1. 范围与已确认结论

| # | 结论 |
|---|---|
| 1 | **单向**：视觉发、电控收；v1 不定义任何回传帧，视觉端不加接收状态机 |
| 2 | **只发两项信息**：有无目标、yaw 偏差；不发 pitch、绝对坐标、5 秒预测值、距离、置信度、发射/击发/力度指令 |
| 3 | **`YAW` 用原图像素值**，不用角度 |
| 4 | **右正左负靠 int16 符号表达**，不设单独的方向位或符号位 —— 这就是删掉 FLAGS 的原因 |
| 5 | 帧里不设模式、不设版本字段、不设序号、不设保留位、不设帧尾；版本由 `SOF + 帧长` 识别（见 §4） |
| 6 | CRC16 保留：这是 v0 裸帧最需要补的安全底线，不属于"信息字段"，不删 |

**为什么不加 CRC8**：参考战队用它保护变长裁判帧的帧头。本协议定长 6 字节，按长度滑窗 + 整帧 CRC16 一次校验即可完成同步，不需要额外的头校验。

**为什么不用帧尾**：v0 用 `0x0D` 作帧尾，但 `YAW` 数值本身可能含 `0x0D`；定长 + CRC 同步没有这个歧义。

## 3. 物理层

| 项 | 约定 |
|---|---|
| 逻辑链路 | UART 异步串行字节流，115200 baud，8N1，无流控，无奇偶校验 |
| 物理实现 | 视觉端（TL3576-MiniEVM）USB 口接 **USB-TTL 转接板**，引出 TTL 三线 `TX / RX / GND` 接电控（交叉、共地） |
| 电平 | 转接板跳线选 **3.3 V TTL**；双方 IO 电平需实测一致，不一致必须加电平转换，**禁止 1.8V / 5V 直连** |
| 端口 | 由 [camera_config.yaml](../Camera/camera_config.yaml) 的 `vision.serial_port` 提供，当前配置为 `/dev/ttyUSB0`（USB-TTL），**不硬编码在代码里**；换板子 / 换口只改配置 |
| 专用性 | 该串口**只跑本协议**，不得混入日志、调试打印或 shell 输出；**禁止使用 UART0 / `/dev/ttyFIQ0`**（板端实测：`console=ttyFIQ0`、`serial-getty@ttyFIQ0.service` 占用；内核日志会冲掉二进制帧） |
| 线材 | 发射冲击大：屏蔽或双绞、接头锁固、走线避开发射机构与电机动力线 |
| 带宽 | 6 B × 20 Hz = 120 B/s，约占 115200 的 0.8%，无带宽压力 |

> 协议只依赖"一条干净的 8N1 字节流"，物理层走 USB-TTL 只影响接线与
> `vision.serial_port` 取值；帧格式、CRC、示例帧与电控端要求（§4~§9）**完全不变**。

### 3.1 备选：UART10 实测为 disabled（本方案不采用）

| 项 | 实测（2026-11-12，只读检查） |
|---|---|
| 设备树别名 | `serial10 = /serial@2afc0000` |
| 节点状态 | **`status = "disabled"`**，系统无 `/dev/ttyS10`（只有 ttyS1/ttyS2/ttyS8） |
| 默认引脚 | `uart10m0-xfer` = GPIO3_B0 + GPIO3_B1（func 9）；备用 m1=GPIO1_D1/D0，m2=GPIO0_C5/C4 |
| 启用代价 | dtb 打包在 boot 分区 `/dev/mmcblk0p3` 的 U-Boot FIT 镜像里，内核 `CONFIG_OF_OVERLAY is not set`，只能改源码重编 dtb 并重新烧写 boot，有变砖风险 |

结论：UART10 不是"插上就能用"的引脚，需改设备树+烧写固件。当前改用 **USB-TTL**（`/dev/ttyUSB0`）：插上即识别、零固件风险，代码无需改动。

## 4. 帧格式（定长 6 字节）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `SOF` | u8 | 固定 `0xA5` |
| 1 | `TARGET` | u8 | **0 = 无目标，1 = 有目标**；其余取值视为无效帧 |
| 2..3 | `YAW` | **int16 LE** | **原图像素偏差，右正左负**，二进制补码小端；饱和到 `[-32768, 32767]` |
| 4..5 | `CRC16` | u16 LE | CRC-16/MODBUS，覆盖 byte 0..3，**低字节在前** |

### 约定

- `TARGET = 0` 时 `YAW` **必须填 0**，电控必须忽略它；`TARGET = 1` 时 `YAW` 才有效。
- **方向不需要单独字段**：`YAW` 为正表示目标在瞄准线右侧、电控应向右修正；为负表示偏左。正负号本身就是方向信息，故 FLAGS 整个删掉。
- `YAW = 0` 且 `TARGET = 1` 是**真实对准**，与 `TARGET = 0` 的"无目标"完全不同，电控必须区分。
- 版本不占字节：**`SOF = 0xA5` + 帧长 6 唯一确定 v1**。将来若要加 pitch / 序号 / 置信度，改用新 `SOF`（如 `0xA6`）+ 新帧长，双方按 `SOF` 分流，不做字段级版本协商。
- 所有多字节字段均为**小端**；`CRC16` 校验值本身也按低字节在前存放。

### CRC16 参数

| 参数 | 值 |
|---|---|
| 算法 | CRC-16/MODBUS |
| 初值 | `0xFFFF` |
| 多项式 | `0xA001`（反射形式，等价 `0x8005`） |
| 输入/输出反射 | 是 / 是 |
| 异或输出 | `0x0000` |
| 覆盖范围 | byte 0..3（不含 CRC 自身） |
| 存放 | `frame[4] = crc & 0xFF`，`frame[5] = crc >> 8` |

该参数与参考战队 [CRC_Check.c](../reference/2025RobMaster-Flying-Dart-Embedded-main/2025RobMaster-Flying-Dart-Embedded-main/Application/CRC_Check.c) 的 `Append_CRC16_Check_Sum` 完全兼容（已用逐位算法与查表法交叉验证）。

## 5. 数据定义

```
yaw = round( 滤波后绿灯灯心 x  −  (原图宽度 // 2 + yaw_aim_offset_px) )
```

- 单位：**原图像素**；**右正左负**；不使用显示缩放坐标、不使用标定主点、不使用模型框中心。
- 数据来源 [DetectionTypes.hpp](../Vision/DetectionTypes.hpp) 的 `VisionResult.yawOffsetPixels` / `yawOffsetValid` / `captureTimestamp`。
- 四舍五入后 clamp 到 int16；`NaN`、无穷、无效结果一律不进帧。
- 有效性：`yawOffsetValid == true` **且** 当前帧有观测 **且** `now - captureTimestamp <= serial_max_age_ms`。
- **不发送 5 秒预测值，不发送内参光轴视线角**（弧度），二者只用于显示与调试。
- **绝不允许用 `TARGET = 1, YAW = 0` 伪装有效目标**；真实对准时发的就是这一组合，靠 `TARGET` 与"无目标帧"区分。

### 5.1 量纲：为什么发像素、不发角度（25 m 单目）

已确认按像素发送，理由是链路精度而不是传输方便：

1. 单目像素 → 角度需要内参（`fx`、主点）、畸变参数，以及**相机与镖架 yaw 转轴之间的安装外参**；在 25 m 距离上，1 像素对应的角度很小，内参或安装姿态的一点点误差都会被放大成落点偏差。比赛现场不具备可靠复标条件，**在视觉端做这个换算等于把不可控误差固化进协议**。
2. 电控 PID 本来就是按像素误差闭环的（参考报告 `pid->err = |e|·e/2`）。视觉只给原始像素差，量纲换算、非线性、增益全部留在电控侧，现场可直接调，出问题也能一眼看出是"偏了多少像素"。
3. 距离固定时像素偏差与角度近似线性，**没有必要多一层换算**；固定 25 m 反而让像素方案更稳。
4. 换相机 / 换镜头后只需重标 `yaw_aim_offset_px` 并重整电控 PID 增益，**帧格式不用改** —— 解耦靠"视觉端保持帧语义不变"，不靠改帧结构。

## 6. 发送策略

| 情况 | TARGET | YAW | 说明 |
|---|---|---|---|
| 有目标，有偏差 | 1 | 偏差值 | 正常控制帧，符号即方向 |
| 有目标，已对准 | 1 | **0** | 有效零，电控可继续跟随 |
| 丢目标 / 结果过期 / NaN / 推理失败 | **0** | 0 | **显式无目标帧**，表示"链路活着但没找到" |
| 程序启动、退出前、串口未使能 | — | — | **停发**，电控靠超时进入不跟随 |

- 周期 **50 ms（20 Hz）**，独立发送线程，只取"最新结果"快照，不排队、不阻塞采集与推理。
- 无目标帧**照常按 50 ms 发**，电控只要还在收帧就知道线没断；完全收不到帧才判超时。这样不需要序号字段也能区分"没目标"和"断链"。
- 与 v0 的关键差异：v0 丢目标直接**停发**，电控只能靠超时猜；v1 用 `TARGET = 0` 明确告知，同时**仍保留独立接收超时**做兜底。
- 半帧保护：单次写 50 ms 内未写完则**停止发送线程**，绝不把半帧和下一帧拼接（沿用 [SerialOutput.cpp](../Vision/SerialOutput.cpp) 现有逻辑）。
- 串口打不开只告警，不拖死取流；真实断线需检查接线后重启程序，不自动重连。
- `serial_max_age_ms` 现为 500 ms（调试初值），**建议按实测推理延迟收紧到 200 ms 以内**，且必须早于电控超时（见 §10）。

## 7. 电控端（接收方）必须实现 —— 过审需电控同学确认

1. 按 `0xA5` **字节滑动同步** → 收满 6 字节 → 校 CRC16；失败整帧丢弃并重新同步。**严禁按 `0x0D` 或任意分隔符切帧，严禁解析半帧。**
2. **独立接收超时 `RX_TIMEOUT_MS = 200`（4 个发送周期）**：超时立即退出视觉跟随、yaw 输出归零或保持、**禁止自动发射**。该超时不得依赖视觉端停发。
3. `TARGET == 0` 时忽略 `YAW`，不得把 0 当作"已对准"；`TARGET` 非 0/1 的帧按无效丢弃。
4. 严格区分三种状态：**没收到包** / **收到无目标帧** / **收到有效零**。
5. 上电 / 复位默认**不跟随**；建议连续收到 **3 帧** `TARGET = 1` 才进入跟随，避免单帧毛刺触发动作。
6. 视觉数据**只用于 yaw 跟随**，不得据此触发击发 / 发射 / 力度调整。
7. 任何解析异常都不得沿用上一帧 `YAW`。
8. **方向符号需联调确认**：本协议约定"右正左负"是图像坐标，电控电机正方向可能相反；第一次接电机前必须用小偏差实测转向，必要时在电控侧取反（**不要改视觉端符号**）。
9. CRC16 按**低字节在前**解析（见 §10 待确认项）。

## 8. 示例帧（CRC 已实测，十六进制）

| 场景 | 完整 6 字节 | CRC16 |
|---|---|---|
| 有目标，`YAW = +123 px`（偏右） | `A5 01 7B 00 51 D8` | `0xD851` |
| 有目标，`YAW = −123 px`（偏左） | `A5 01 85 FF 51 F8` | `0xF851` |
| 有目标，已对准（**有效零**） | `A5 01 00 00 73 28` | `0x2873` |
| 无目标（invalid，**非对准**） | `A5 00 00 00 22 E8` | `0xE822` |
| 有目标，`YAW = +2000 px` | `A5 01 D0 07 6F 2A` | `0x2A6F` |

CRC 低字节在前，例如第一帧校验值 `0xD851` 落地为 `51 D8`。
注意 `YAW` 数值里出现 `0x0D` 完全合法，接收端**必须按 6 字节定长取帧**，不能按字节内容找分隔符。

## 9. 安全约束（硬性，不可协商）

- 视觉端**永不发送**发射 / 击发 / 力度 / 归位指令；帧里没有任何此类字段。
- 电控超时保护必须独立实现，视觉端停发只是配合，不是保护。
- 上电、异常、CRC 失败时默认不跟随。
- 视觉端不得因视觉数据自行改变控制权限或触发任何机械动作。
- 新旧帧**互不兼容**：禁止一端先升级、另一端仍用 v0 解码程序。

## 12. 与 v0 的兼容说明

旧实现是 `FF | int16 yaw_px LE | 00 00 00 00 | 0D`（8 字节，无 CRC / 无目标状态位），见 [SerialYawProtocol.md](SerialYawProtocol.md)。

v1 改为 `0xA5` 帧头 + **定长 6 字节** + CRC16，帧长、帧头、字段含义**全都变了，两者完全不兼容**。视觉端编码与测试已按 v1 替换；切换电控时必须同时替换其解码程序，不要一端新一端旧。串口默认仍关闭（`enable_serial: 0`），不会误发。
