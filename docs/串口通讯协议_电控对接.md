# 飞镖镖架 视觉 → 电控 串口通讯协议 v1.0

> 本文件为**双方对接接口约定**，可直接照此实现解码程序。
> 版本：v1.0 ｜ 日期：2026-11-11

---

## 1. 链路总览

| 项 | 约定 |
|---|---|
| 方向 | **视觉端 → 电控，单向 TX**（电控不需要回传） |
| 逻辑链路 | **UART 异步串行字节流**，115200 baud，8N1，无流控，无奇偶校验 |
| 物理实现 | 视觉端（TL3576-MiniEVM）USB 口接 **USB-TTL 转接板** 引出 TTL 三线 `TX / RX / GND` 接电控，见 §1.1 |
| 电平 | 转接板跳线选 **3.3 V TTL**；双方 IO 电平需实测一致，不一致必须加电平转换，**禁止 5 V / 1.8 V 直连** |
| 共地 | `GND` 必须与电控共地 |
| 端口 | 该串口**专用**，不得混入日志或调试打印；**禁止使用被 console / getty 占用的调试串口** |
| 发送周期 | **50 ms（20 Hz）** |
| 帧长 | **定长 6 字节** |

### 1.1 视觉端接线与设备节点（TL3576-MiniEVM · USB-TTL）

```text
TL3576-MiniEVM USB 口 ── USB-TTL 转接板（CH340C / CP2102 / FT232，跳线 3.3V TTL）
                            TX  → 电控 RX      （交叉）
                            RX  → 电控 TX
                            GND → 电控 GND     （共地）
                            VCC → 不接
```

- 板子侧设备节点为 **`/dev/ttyUSB0`**（已有其他 USB 串口时顺延），填入 `vision.serial_port`。
- 内核已内建 `usbserial` 与 cp210x / FTDI / pl2303 驱动，**插上即识别，无需装驱动**；当前用户在 `dialout` 组，可直接读写。
- 该口是 USB 新枚举的串口，与板载 UART / 调试口互不相干，不改设备树、不动固件。
- **UART0 / `/dev/ttyFIQ0` 不可用**（板端实测：`console=ttyFIQ0` + `serial-getty@ttyFIQ0` 占用，
  内核日志会冲掉二进制帧）。

> 无论走哪条物理链路，两端看到的都必须是同一条干净的 8N1 字节流；
> **帧格式、CRC、示例帧与电控端要求（§2~§6）完全不变**，仅 `vision.serial_port` 取值不同。

## 2. 帧格式

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `SOF` | u8 | 固定 `0xA5` |
| 1 | `TARGET` | u8 | `0` = 无目标，`1` = 有目标；其余取值视为无效帧 |
| 2..3 | `YAW` | **int16 LE** | 原图像素偏差，**右正左负**，二进制补码小端；饱和到 `[-32768, 32767]` |
| 4..5 | `CRC16` | u16 LE | CRC-16/MODBUS，覆盖 byte 0..3，**低字节在前** |

所有多字节字段均为小端；CRC 校验值本身也按低字节在前存放：
`frame[4] = crc & 0xFF`，`frame[5] = crc >> 8`。

## 3. 字段语义

- `YAW = 当前绿灯灯心 x − 瞄准线 x`，单位是**原图像素**（当前原图 1440×1080，瞄准线默认为图像水平中心）。不使用显示缩放坐标。
- **符号即方向**：`YAW > 0` 目标偏右、电控向右修正；`YAW < 0` 偏左。不设单独方向位。
- `TARGET = 0` 时 `YAW` 固定填 `0`，**电控必须忽略该值**；这是「链路正常但没找到目标」，不是对准。
- `TARGET = 1` 且 `YAW = 0` 是**真实对准（有效零）**，与上一条完全不同，务必区分。
- 帧内**只有 yaw 一个控制量**，不含 pitch、预测坐标、距离、发射/击发/力度指令。

## 4. CRC16

| 参数 | 值 |
|---|---|
| 算法 | CRC-16/MODBUS |
| 初值 | `0xFFFF` |
| 多项式 | `0xA001`（反射形式） |
| 输入/输出反射 | 是 / 是 |
| 异或输出 | `0x0000` |
| 覆盖范围 | byte 0..3（不含 CRC 自身） |

参考实现（可直接复制）：

```c
#include <stdint.h>

uint16_t crc16_modbus(const uint8_t *p, int len) {
    uint16_t crc = 0xFFFF;
    while (len--) {
        crc ^= *p++;
        for (int i = 0; i < 8; ++i)
            crc = (crc & 1) ? (uint16_t)((crc >> 1) ^ 0xA001)
                            : (uint16_t)(crc >> 1);
    }
    return crc;   /* 低字节先发 */
}
```

校验时对整个 6 字节帧的前 4 字节重算，与 `frame[4] | frame[5] << 8` 比较。

## 5. 示例帧（十六进制）

| 场景 | 6 字节 |
|---|---|
| 有目标，`YAW = +123 px`（偏右） | `A5 01 7B 00 51 D8` |
| 有目标，`YAW = −123 px`（偏左） | `A5 01 85 FF 51 F8` |
| 有目标，已对准（**有效零**） | `A5 01 00 00 73 28` |
| 无目标（**非对准**） | `A5 00 00 00 22 E8` |
| 有目标，`YAW = +2000 px` | `A5 01 D0 07 6F 2A` |

> `YAW` 数值里出现 `0x0D` 等字节完全合法，接收端**必须按 6 字节定长取帧**，不能按字节内容找分隔符。

## 6. 电控端必须实现

1. 按 `0xA5` **字节滑动同步** → 收满 6 字节 → 校 CRC16；校验失败整帧丢弃并重新同步，**严禁解析半帧**。
2. **独立接收超时 200 ms**（4 个发送周期）：超时立即退出视觉跟随、yaw 输出归零或保持，**禁止自动发射**。该超时不得依赖视觉端停发。
3. `TARGET = 0` 时忽略 `YAW`；`TARGET` 非 0/1 的帧按无效丢弃。
4. 严格区分三种状态：**没收到包** / **收到无目标帧** / **收到有效零**。
5. 上电默认**不跟随**；建议连续收到 3 帧 `TARGET = 1` 才进入跟随，避免单帧毛刺触发动作。
6. 视觉数据**只用于 yaw 跟随**，不得据此触发击发、发射或力度调整。
7. 任何解析异常都**不得沿用上一帧 `YAW`**。
8. **方向符号需联调确认**：本协议「右正左负」是图像坐标，电机正方向可能相反；首次接电机前用小偏差实测转向，必要时在**电控侧**取反（不要改视觉端）。
