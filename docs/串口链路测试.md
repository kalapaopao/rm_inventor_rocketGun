# 串口链路测试

用一条命令验证**项目正式的发送模块**能不能把帧送到电控：

```bash
cd /rm_inventor_fly
sudo systemctl stop dart-vision.service     # 先停服务，避免抢串口
./build/Camera/show --serial-test           # Ctrl+C 结束
```

## 它做什么

不打开相机、不启动视觉管线，直接实例化正式发送模块 `vision::SerialOutput`，
只把"目标来源"换成恒为"无新鲜结果"，于是每个周期发出协议 v1 的无目标帧：

```text
A5 00 00 00 22 E8      SOF=A5, TARGET=0, YAW=0, CRC16-Modbus
```

这与正式运行中"链路活着但视野内没目标"走的是**同一条代码路径**：同一个 `SerialOutput::loop`、
同一个传输层、同一套半帧保护。所以它 PASS，就说明项目能正常发帧给电控。

参数全部取自 `Camera/camera_config.yaml`：

```yaml
vision:
  serial_port: "/dev/ttyUSB0"
  serial_backend: "auto"      # auto / tty / ch341
  serial_baud: 115200
  serial_period_ms: 50
```

## 传输后端（重要）

板端内核 `6.1.115-rt16-g469da534041d` 的配置是 `# CONFIG_USB_SERIAL_CH341 is not set`，
且驱动全部编进内核镜像（无 `/lib/modules`），所以 CH340/CH341 **不会产生 `/dev/ttyUSB0`**。
为此发送模块有两条传输路径，由 `serial_backend` 选择：

| `serial_backend` | 行为 | 适用硬件 |
|---|---|---|
| `auto`（默认） | 设备节点存在 → 内核 tty；不存在 → libusb 用户态直驱 CH341 | 两者都兼容，换板子无需改配置 |
| `tty` | 只用内核 tty 设备 | CP2102 / FT232 / CDC-ACM |
| `ch341` | 只用 libusb 直驱 CH341/CH340 | CH340/CH341（无内核驱动时） |

> `auto` 的优先级是"有节点走 tty"——CP2102/FT232 插上后自动走内核路径，比用户态更稳。

### CH341 需要 udev 规则

用户态直驱要普通用户能打开 USB 设备节点，否则 `libusb_open` 报
`LIBUSB_ERROR_ACCESS`，表现为 `[SerialOutput] cannot open ...: 找到 CH341 但打不开`。
安装一次即可：

```bash
sudo cp tools/99-ch341.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger --subsystem-match=usb
ls -l /dev/bus/usb/001/    # 该设备应变为 crw-rw-rw- root plugdev
```

## 输出与判据

每秒一行，同时打印**实际发送的字节**，帧数递增即证明真的在跑：

```text
[link] 串口自检 /dev/ttyUSB0 @115200 8N1 / 50ms
[link] 发送帧 A5 00 00 00 22 E8  (SOF=A5 TARGET=0 YAW=0 CRC16)
[SerialOutput] started on libusb:ch341 @115200, period 50 ms
[link] 1s 帧=20 错误=0 20.0Hz  发=A5 00 00 00 22 E8
[link] 2s 帧=40 错误=0 20.0Hz  发=A5 00 00 00 22 E8

[link] 108 帧 / 648 B / 0 错误 / 5.4 s / 20.0 Hz
[link] PASS：正式发送模块正常，项目可发帧给电控
```

`[SerialOutput] started on ...` 里的 `tty:` / `libusb:ch341` 就是**实际使用的后端**。

| 输出 | 含义 |
|---|---|
| `PASS` | 正式发送模块正常，项目能发数据给电控 |
| `cannot open ...: 未找到 CH341/CH340` | 转接板没插好/没枚举 |
| `cannot open ...: 找到 CH341 但打不开` | 缺 udev 规则或权限 |
| `cannot open ...: cannot open /dev/ttyUSB0` | 节点不存在（tty 后端），检查驱动或改用 auto |
| `FAIL：发送线程中途停止` | 写错误触发半帧保护，正式运行也会停发 |

> Ctrl+C 与写操作竞争时，发送线程可能在退出瞬间停掉并留下一次写错误。
> 这是退出时序而非链路故障：主动结束时工具打印"非链路故障"并仍判 PASS。

## 实测记录

| 日期 | 场景 | 结果 |
|---|---|---|
| 2026-11-18 | PTY 虚拟串口（tty 后端） | PASS，108 帧全部 CRC 正确、0 重同步 |
| 2026-11-18 | 真实 CH341 + 拓展坞（auto→libusb:ch341） | **PASS**，108 帧 / 0 错误 / 20.0 Hz |
| 2026-11-18 | 独立 libusb 工具长跑 | 2389 帧 / 0 错误，但期间出现间歇 USB 掉线 |

**已知问题**：CH341 用户态路径在长时间测试中出现过间歇性 USB 掉线
（`LIBUSB_ERROR_NO_DEVICE`，几十秒到几分钟不等），与拓展坞无关。比赛前建议换
**CP2102 / FT232** 走内核 tty；若继续用 CH341，务必用 `--serial-test` 跑满一场比赛的时长确认稳定。

## 接线检查清单

| 项 | 要求 |
|---|---|
| TX/RX | 板 TX → 电控 RX，板 RX → 电控 TX（**交叉**） |
| GND | **必须共地**，否则收不到也容易把芯片拉挂 |
| 电平 | 转接板跳线 **3.3 V TTL**；禁止 5 V / 1.8 V 直连 |
| 串口参数 | 双方 115200、8N1、无流控 |
