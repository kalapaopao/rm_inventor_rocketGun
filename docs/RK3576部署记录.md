## 构建与验证结果

板端执行：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DMVS_ROOT=/home/Tronlong/apps/rm_inventor_fly-89fe1cf-20261111/sdk/MVS
cmake --build build -j2
./build/Vision/vision_geometry_test ./camera_intrinsics.yaml
./build/Vision/vision_serial_test
```

完整构建到`[100%] Built target show`；传统管线、内参、5秒预测、像素偏差和PTY串口测试输出PASS。
PTY测试中模拟断线的`incomplete/error write`是预期故障注入，不是真实串口故障。
`bash tools/run_rk3576.sh --help`正常输出参数。
实际无窗口启动尝试返回`No Hikrobot camera found.`，SDK还输出`XOpenDisplay Fail`；
当时`lsusb`仅列USB集线器/键鼠，没有海康设备，未完成真实取流。

遇到并处理/保留的问题：
- SSH/SCP最初被拒绝，恢复连接后使用`scp -O`完成传输。
- 缺MVS时首次完整CMake配置失败；加入项目内ARM64 SDK路径后构建成功。
- 一次MVS_ROOT命令变量引用导致路径错误，改成绝对路径后成功。
- 板端日期实测为2025-08-27，与源码/系统头文件时间不一致，引发Clock skew警告；
  只调整部署副本时间戳，没有修改系统时钟。系统头文件仍来自未来，所以警告仍可能存在。
- 早期启动脚本每次重编译，短时timeout测试中断过一次重复构建；已改为默认运行
  现成二进制，显式`--rebuild`才重新构建，随后`--help`与相机枚举正常执行。

## 启动

将海康相机接到RK3576 USB3口，在板子桌面终端执行：

```bash
cd /home/Tronlong/apps/rm_inventor_fly-89fe1cf-20261111
bash tools/run_rk3576.sh --window
```

无桌面SSH会话用`bash tools/run_rk3576.sh`运行无窗口模式。
需要重编译时：`bash tools/run_rk3576.sh --rebuild --window`。
不要用原WSL启动脚本代替此启动器；本地SDK位于项目内，而非`/opt/MVS`。
若相机已出现却提示权限错误，应先确认USB节点权限和SDK说明，不要直接chmod全部设备。
